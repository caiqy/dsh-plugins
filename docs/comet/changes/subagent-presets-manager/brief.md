# Outcome

在 DSH 设置左侧增加“Subagent 预设”入口，打开主工作区的完整管理页，自动展示插件实际读取的 Markdown 角色预设，让用户无需手工编辑文件即可新增、复制、编辑、原文修复和删除。保留 DSH 0.2.0-rc.2 与 0.2.1-alpha.2 双支持线。

# Scope

只扩展 `packages/dsh-subagent-registry`，复用配置解析出的 agentsDir 与原有文件、运行时解析规则及派发机制。设置只承担入口，列表及独立表单在 main 工作区页面切换。基本表单包含内部名称、显示名、职责描述、模型、思考强度和系统提示词；高级字段为深度、后台运行及轮数上限。所有继承值保持原语义。错误文件仍展示并提供独立原文修复页。

界面和文件读写均使用插件公开扩展：共有 `settings.section` 与 `main` 插槽；宿主 `connection.rpc.handle` / 客户端 `connection.rpc.call` 通道复用 Host/Origin fence 和身份认证，模型目录用现有 `remote.session.modelCatalog`。不直接暴露未认证 webServer 写路由。

# Non-goals

回收站、导入导出、批量编辑、分类标签、全量 YAML 编辑器、跨 profile 迁移、历史会话身份修改、额外目录/派发策略设置。无外部发布、push 或 PR。只操作测试隔离目录，客户端验收不得改删用户现有角色；交付安装过程保留原包回退资料。

# Constraints and invariants

- 原 Markdown 是唯一事实来源；UI 不因读取失败或删除全部角色而补默认文件。
- 非法/重名输入、外部版本冲突和真实磁盘错误不得报告成功或破坏原文。
- 结构化保存只改明确编辑字段和正文；保留未知字段、注释和未编辑原文。无法安全保留的结构必须明确转入原文修复。
- 只接受安全文件标识，防止越界路径、平台保留名、目标符号链接；认证通道不是输入校验的替代。
- 不重启整个插件刷新名册，不重新派发或终止已有任务；前后台派发、续跑、追问、叶子限制、现有英文指导保持。
- 同包使用宿主 SDK 单实例，不把 React/Cordis/宿主组件重复打包。

# Decisions

- Q1-Q11采用已确认设计，包括设置入口打开 main 独立管理页。
- 工作区由用户选择 A：当前目录及 main 分支；只将本需求设计与实现纳入交付。
- 单个 Native change：文件写入、注册刷新和界面共享同一数据语义，验收需要端到端联动，拆多个正式子 change 增加协调成本；允许限定职责的子代理调查/实现及新 reviewer 独立验收。
- 通信选用公开 Connection RPC，不新增生成的 remote 命名空间、不自行处理身份令牌。
- 当前两版 `ILayout.selectPanel` 无公开离页 veto；`beginNavigation` 是取消异步导航而非拦截。普通 main 页无设置 open/openSection 服务。不得靠覆写宿主对象或全局 DOM 捕获伪装成公共集成。

- Q12用户选择A：管理页内返回列表、取消和刷新等会丢弃输入的操作先确认；切换宿主其他页时不弹确认，草稿保留在当前客户端，回来继续。返回设置使用宿主现有设置按钮。内存草稿不保证跨客户端重启、插件卸载或开发HMR保留；不提供程序化返回指定设置页。

# Implementation plan

1. 先实现共享文件读写/校验和最小Connection RPC契约，写一个可运行的隔离目录检查，验证原文保真、重名及冲突拒绝、路径/链接边界；只读当前用户预设用于确认实际格式。
2. 按统一数据契约实现客户端入口、main独立页面和插件生命周期草稿；复用已有控件和主题。后端与前端可委派给匹配角色，各自只修改明确文件，父代理负责公共契约、名册刷新和组合。
3. 调整同包manifest、声明和客户端factory构建，完成真实两SDK的认证通道、页面/草稿、名册更新及既有生命周期定向检查，随后实际打包安装验证。
4. 提交候选后由Comet Runtime执行正式检查，新的只读reviewer独立核对A1-A10；修复与复验按Native循环，用户接受结果后归档交付。

# Verification expectations

定向检查与当前候选一致后交由 Runtime 冻结正式检查；两个实际发布 SDK 使用独立进程验证同包。包括认证失败401/不可信Origin403且文件未变、危险文件标识/符号链接拒绝、真实CRUD和版本冲突、保真更新、客户端加载/导航/草稿/确认、正在执行任务与刷新交错、native/PTC及scope限制。需实际加载编译包并验证当前客户端；未执行的两版GUI操作不能由SDK类型比对冒充通过。明确脚本化模型与外部模型、组件与实机验收边界。

# Acceptance examples

- A1：打开管理页自动读取实际配置目录，显示正常角色、错误文件和诊断；区分加载中、空目录和读取失败，不补默认预设，保留已有排序。
- A2：两版出现独立“Subagent 预设”设置入口，打开主工作区完整管理页；创建、复制、编辑、修复是独立视图而非列表行内表单；高级字段折叠，主题、键盘、字段标签和窄屏可用。
- A3：空白创建及复制覆盖全部支持字段与正文、继承语义及模型目录/自定义路由；新名称安全且唯一，旧内部名称只读、不能通过修复改成另一个标识；错误字段就地提示，不覆盖源或重名文件。
- A4：错误角色仍列出原因；修复页显示完整原文，按运行时规则验证并纠正目标文件身份；错误保存不生效，原文和草稿保留。
- A5：保存失败、版本冲突和取消放弃/刷新确认保留草稿；管理页内会丢弃输入的动作先确认。切到宿主其他页不弹确认，回到管理页继续当前客户端草稿；使用宿主设置按钮返回设置。重启客户端或卸载插件不保证草稿恢复。
- A6：删除有具体目标及共享影响确认且只删除该文件；CRUD经宿主身份/Origin保护并验证输入和配置目录边界；无认证或非法路径/链接请求不修改文件，读写/删除错误明确可见。
- A7：结构化更新保留额外字段、注释及未编辑正文；不能安全更新时引导原文编辑；保存和删除检测外部变化，创建不覆盖，失败不留下半写文件且草稿保留。
- A8：新建、保存、删除、打开页面和手动刷新同步列表及模型名册，后续模型请求无重启生效；正在执行的工具调用和后代任务不被中断；权限、scope及PTC可见性保持。
- A9：显示名增加、清除或修改前确认历史按名续跑/追问影响；不改历史记录，现有前台/后台/续跑/追问、叶子工具限制及英文指导回归通过。
- A10：同一编译包在真实0.2.0-rc.2及0.2.1-alpha.2闭包验证新增功能及既有生命周期回归，包内客户端和声明齐全、安装生命周期开启可加载；当前客户端实际加载验收并清楚记录安装、构建、重启生效边界，经过Comet独立全项验收。
