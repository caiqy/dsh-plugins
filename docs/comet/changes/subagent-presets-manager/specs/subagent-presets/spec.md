# Subagent 预设管理

## 范围与数据源

以 dsh-subagent-registry 的当前 agentsDir 为唯一预设来源，默认值沿用 DSH_HOME/agents 解析。不同 profile 指向同一目录时共享预设。仅加载顶层普通 Markdown 文件，不迁移目录、不另建数据库、不擅自覆盖或补默认角色。入口名称为“Subagent 预设”，与会话组合预设及委派限额设置明确区分。

## 自动列表与错误文件

正常行展示内部名称、显示名、职责描述、模型/继承默认和状态，提供编辑、复制、删除。错误行显示文件名、解析错误或名称/文件身份不一致的原因，提供原文修复和删除。沿用既有顺序，区分加载中、空目录和读取失败；读取失败不能伪装成空列表。显示配置实际目录与共享提示。

### Scenario: 自动加载目录

Acceptance: A1

GIVEN 配置目录含合法角色、无效frontmatter和名称不一致文件，WHEN 打开管理页或手动刷新，THEN 展示正常及错误条目与具体诊断，来源为实际配置目录。空目录显示空状态，权限/目录错误显示真实读取失败，均不植入角色文件。

## 入口与独立页面

在 settings.section 注册轻量导航入口，打开 main keyed root 工作区页面并关闭设置面板。管理页内部有列表、空白新增、复制、编辑和原文修复视图；新增和编辑不能在列表行内展开。复用两版共同原生控件和宿主主题tokens、明确标题、字段标签、键盘操作与焦点反馈，高级项折叠。不得依赖某版独有控件或内部样式模块。

### Scenario: 设置入口与表单页面

Acceptance: A2

WHEN 点击设置左侧“Subagent 预设”，THEN 在主工作区打开完整管理页；点击新增/复制/编辑/修复进入独立页面，返回列表入口明确，窄屏不遮挡关键操作，字段有标签且可用键盘完成，沿用主题和高级字段折叠。

## 表单与身份

基本字段为内部名称、显示名、职责描述、模型、思考强度和系统提示词正文。创建/复制需新的唯一安全名称，新文件名等于内部名称；编辑内部名称只读。已有缺失/错配名称通过原文修复纠正为当前目标文件标识，不能改名成其他预设。复制读取原内容，不修改源文件。

模型可继承默认，从已有 remote.session.modelCatalog 目录提供选项，保留自定义或暂不可用provider/model值；模型目录加载失败不能清空已存路由。思考强度继承或off/low/medium/high/max。高级字段是deep、background、maxRounds；缺省分别为深度1、前台和全局轮数，不把缺省写成新的覆盖。验证沿用当前运行时parseAgentMarkdown，不建立相互矛盾的UI字段语义。正文使用普通多行文本区保留Markdown。

### Scenario: 新建复制与完整字段保存

Acceptance: A3

GIVEN 现有预设具有自定义路由、缺省高级值和Markdown正文，WHEN 新建、复制或编辑，THEN 可以正确读取和保存全部支持字段、继承值及正文，复制源不变；名称非法/重名及字段错误有就地提示，旧名称只读且不得覆盖其他角色。模型目录失败不清除原值。

## 错误文件与原文修复

原文修复页展示完整原文和错误原因，按相同运行时解析器及文件身份规则验证。合法修复后保存并刷新；仍非法时保留草稿和诊断，不宣称生效。无法安全保真做表单更新的文档也引导到明确的原文编辑路径，而不是静默重写。

### Scenario: 修复错误文件

Acceptance: A4

GIVEN 列表中的错误文件，WHEN 打开修复并输入仍不合法的内容，THEN 原文、草稿和具体诊断保留、不报告保存成功；纠正为合法内容及目标身份后才保存并进入可调用名册。

## 草稿与导航

保存失败、外部版本冲突均保留输入；返回列表、取消、刷新等插件自身可能丢弃输入的动作先提醒确认。草稿必须位于插件客户端生命周期内，不因为React组件卸载清空。

Q12已确认A：宿主切页时不弹确认、保留本客户端内存草稿，重新通过设置入口回来继续；返回设置使用宿主既有按钮，不提供程序化返回指定设置页。两条发布宿主的公开ILayout均无全局离页veto，beginNavigation仅取消异步导航；不许通过覆写layout、全局DOM拦截或事后切回冒充公开拦截。内存草稿不承诺跨客户端重启、插件卸载或开发HMR恢复。

### Scenario: 未保存输入保护

Acceptance: A5

WHEN 保存失败、文件冲突或用户取消插件内放弃/刷新确认，THEN 保留当前草稿。WHEN 切到宿主其他页再打开预设管理入口，THEN 不弹全局离页确认且当前客户端草稿仍在，可以继续编辑。返回设置使用宿主按钮，重启客户端或卸载插件不保证草稿恢复。

## 删除与安全边界

删除前展示目标内部名称/文件名及目录共享影响，确认后仅删除目标。保存/删除须提交读取时版本；外部删除或改动拒绝盲目覆盖，失败保留列表/草稿及错误。

浏览器经公共connection.rpc.call调用宿主connection.rpc.handle，继承Host/Origin fence和浏览器身份认证。客户端不读取身份令牌、不直接暴露裸webServer写路由、不新增端口。所有请求在宿主校验结构及支持字段，只接受受限制的文件标识，不接受绝对路径、路径片段、平台保留名、可将读写引向目录外的目标链接。操作根目录由自身配置解析，不由请求指定。使用实际普通文件检查和受保护写入，不将通道认证当成文件输入校验。

### Scenario: 确认删除与拒绝非法请求

Acceptance: A6

WHEN 用户确认删除，THEN 只删确认的文件并报告真实结果；取消不改文件。WHEN 未认证、不可信Origin、非法字段/标识、越界路径或目标符号链接请求进入，THEN 请求被拒绝、其他文件无变化。权限/磁盘/目录错误不报告成功。

## 文件保真与冲突

读取时保留完整原始内容及版本标记。结构化保存只更新用户明确修改的已知字段或正文，保留未知字段、注释、未修改文本和扩展内容；不能以规范化解析结果全量序列化覆盖。若结构不支持安全局部修改，明确转原文编辑。新建不覆盖；保存前重核版本、避免半写/截断；内部并发请求串行校验，任何错误不得清空原文。外部修改/删除冲突保留草稿并要求重新加载，不能默默重试覆盖。

### Scenario: 保真保存与外部冲突

Acceptance: A7

GIVEN 文档含未知字段、注释及未编辑正文，WHEN 只改显示字段，THEN 其他原文内容保持；不能安全局部更新时明确要求原文编辑。WHEN 外部修改/删除后提交保存或删除，THEN 冲突可见且不会覆盖；创建重名和写入失败也不会损坏现有文件，草稿保留。

## 名册与运行任务

打开、保存、新建、删除和显式刷新同步真实文件列表及dispatch工具描述/agent参数名册，后续模型请求使用最新快照。不增加常驻文件监听；外部文件变化通过打开/刷新同步，已有按次读文件仍保留。

仅更新相关工具注册和英文指导的关联，不重新挂载整个插件或取消运行中的dispatch。以同名同scope原有公开注册及精确disposer完成更新，限制规则继续按name生效。ask工具保持，旧请求快照可能仍含旧名册；已启动角色的persona不被改写。所有刷新路径和卸载边界需真实SDK验证，不能仅用对象突变掩盖宿主cache。

### Scenario: 刷新后续名册与任务隔离

Acceptance: A8

GIVEN 有正在执行的角色任务且目录被新增/修改/删除，WHEN 管理页操作成功或刷新，THEN 下一次模型请求和参数描述看到最新名册，已有调用/后代不被停止；global/scoped及native/PTC视图下权限与叶子限制保持，无需重启客户端。

## 显示标签与回归

显示名新增、清除或变更会改变当前插件用来查找历史run的显示标签，保存前明确提示旧任务可能无法按name续跑/追问并确认。同值不重复确认。不修改历史会话标识或原续跑协议。保留双宿主前台/后台、严格resume/fresh、busy/取消/后代/parent disposal、ask精确相关性和现有英文委派指导。

### Scenario: 标签确认与既有功能

Acceptance: A9

WHEN 保存的显示名改变，THEN 先确认历史按名查找影响，取消时不写文件；相同显示名不重复提示。WHEN 运行既有两线生命周期和权限回归，THEN 结果保持且未新增派发策略或历史迁移。

## 双宿主交付

同一包保留宿主入口并声明client导出及dsh.client元数据，客户端产物为共同ModuleLoader工厂协议，不打包宿主React/Cordis等单例。插件Loader挂载后应进入客户端graph，styles/slots/rpc注册按生命周期清理；CLI/TUI没有Web服务时派发工具不能因新增可选UI依赖消失。

分别以0.2.0-rc.2和0.2.1-alpha.2已发布隔离闭包验证真实服务组合及页面/数据/注册边界，核对实际版本与编译产物。实际安装包加载和当前用户客户端验收是独立要求；不得以类型声明、组件测试或脚本化LLM冒充实机。测试使用隔离角色目录，绝不为验收删除/编辑用户现有角色。说明客户端bundle构建、HMR只读产物及当前profile安装/重启的生效边界，不启动替代服务器来宣称现有客户端已更新。

### Scenario: 同包安装及独立验收

Acceptance: A10

WHEN 构建打包并在两条真实发布SDK闭包加载同包，THEN 新增功能、client导出/manifest和既有生命周期回归通过且记录实际版本；当前安装包和客户端加载有实测证据。新只读reviewer按Comet任务独立核对全部验收项，未执行或失败项目不能算通过。

## 非目标

不增加回收站、导入导出、批量编辑、标签分类、全量YAML编辑器、跨profile迁移、历史任务身份改造或额外派发/目录设置，不改宿主、不新增常驻服务，不发布npm或push/PR。
